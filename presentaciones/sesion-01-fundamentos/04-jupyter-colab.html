Jupyter Notebooks: en la nube o en tu máquina

Dos caminos distintos, el mismo destino: escribir y ejecutar código explorando datos.

Transición desde ambientes/uv: «ya vimos cómo instalar dependencias — ahora, dónde vamos a escribir el código».

🧠
El formato

¿Qué es un notebook?

Un documento donde el código se ejecuta en "celdas" pequeñas, una a la vez, con el resultado apareciendo justo debajo — intercalado con texto explicativo, títulos e imágenes.

📓

Notebook

Corre celda por celda, ves resultados al instante. Ideal cuando estás entendiendo datos por primera vez.

📜

Script tradicional

Corre todo de una sola vez, de arriba a abajo. Ideal cuando ya sabes exactamente qué hacer.

Ejemplo cotidiano: el notebook es como un cuaderno de laboratorio, no como una receta que se ejecuta toda de una — vas probando, viendo resultados, ajustando.

🧩
Por dentro

Dos tipos de celda: código y texto

  • Celdas de código: Python real — se ejecutan y muestran su resultado (una tabla, un número, un gráfico) justo debajo.
  • Celdas de texto (Markdown): explicaciones, títulos, notas — para que el notebook cuente una historia, no solo ejecute código.

Este mismo formato es el que van a ver en cada notebook del curso — código y explicación, uno al lado del otro.

Dos formas de usarlo

Dos caminos, mismo destino

Pueden abrir y correr notebooks de dos formas — ninguna es "la correcta", cada una tiene su momento.

Google Colab

En la nube, de Google. No instala nada en tu computador.

Jupyter local

En tu propia máquina, con el ambiente que ya configuramos con uv.

«No importa cuál usen hoy — lo que aprendan en una sirve igual en la otra, es la misma idea de celdas.»

☁️
Google Colab · Paso 1 de 3

Entrar y crear un notebook nuevo

  • Ve a colab.research.google.com
  • Inicia sesión con una cuenta de Google (la misma de Gmail sirve)
  • Clic en "Nuevo notebook" — listo, ya tienes un notebook corriendo en la nube

Muéstralo en vivo si es posible — es literalmente así de rápido, sin instalar nada.

▶️
Google Colab · Paso 2 de 3

Escribir y ejecutar una celda

Escribe código Python en la primera celda y presiona Shift + Enter — o el botón ▶ a la izquierda de la celda.

In [ ]:
print("Hola, ciencia de datos")
Hola, ciencia de datos

El resultado aparece justo debajo, sin salir del notebook. (clic en ▶ para probarlo)

Shift+Enter ejecuta y avanza a la siguiente celda — es el atajo que van a usar todo el curso, en Colab y en local.

📥
Google Colab · Paso 3 de 3

¿Falta una librería? !pip install

!pip install nombre-paquete

El signo ! al inicio le dice a la celda: "esto no es Python, es un comando de terminal" — exactamente lo mismo que vimos en la diapositiva de la terminal.

Ojo: esto solo dura mientras esa sesión de Colab esté abierta — si cierras y vuelves, hay que instalarlo de nuevo.

Conecta con la presentación de motivación: «la terminal no muerde» — este ! es la terminal, escondida dentro de una celda.

💻
Local · Paso 1 de 3

Abrir tu notebook en VS Code

code .

Esto abre VS Code en la carpeta del proyecto. Abre cualquier archivo .ipynb y VS Code lo reconoce automáticamente como notebook — con la extensión de Jupyter, corriendo con el ambiente exacto que configuramos con uv.

Solo falta seleccionar el kernel correcto (arriba a la derecha del notebook) — el mismo ambiente de tu proyecto.

Así vamos a trabajar en clase: mismo notebook, mismas celdas, mismo motor de Jupyter — solo que dentro del editor en vez de en el navegador.

🔁
Local · Paso 2 de 3

Las mismas celdas, la misma lógica

Shift + Enter para ejecutar, celdas de código y de texto, resultados debajo — exactamente como en Colab. Si ya practicaste en uno, ya sabes usar el otro.

Este slide es corto a propósito — el punto es tranquilizar: no hay nada nuevo que aprender aquí.

🔧
Local · Paso 3 de 3

¿Falta una librería? uv add

uv add nombre-paquete

A diferencia de Colab, esto no se pierde: queda guardado en el pyproject.toml y el uv.lock del proyecto, para siempre — la próxima persona que clone el repo ya la tiene.

Esta es la gran diferencia práctica con Colab — vale la pena remarcarla.

⚖️
Sin ganador

¿Cuál uso? — Comparación honesta

  • Colab: no instalas nada, funciona en cualquier computador — pero necesita internet y pierde archivos temporales al cerrar la sesión.
  • Local: funciona sin internet, control total y persistente — pero requiere tener el ambiente bien configurado (lo que ya hicimos).

No hay una respuesta "correcta" — muchos científicos de datos usan ambos según el día.
